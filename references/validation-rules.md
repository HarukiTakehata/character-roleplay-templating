# 校验规则与质检清单

> 从 `SKILL.md` 移出以减少文件体积。工作流中需要时加载本文件。

## 交叉验证规则

| 置信度 | 条件 | 模板标记 |
|:-------|:-----|:---------|
| 高 | 3+ 个来源一致 | 无需标记 |
| 中 | 2 个来源，部分重叠 | 在来源表中注明 |
| 低/单一 | 仅 1 个来源 | 模板中标记 `[单源]` + 用户提醒 |

## 质量检查清单

完成全部 6 步工作流后，逐项确认：

- [ ] 每个数据类别至少尝试 2 个来源
- [ ] 主模板无 Emoji
- [ ] 所有文件中无简历/CV、版本号或发布日期
- [ ] 来源章节存在，含 URL 和状态
- [ ] Token 高效：表格/要点优先于散文
- [ ] prompt.md 自包含（可独立粘贴使用）
- [ ] SOUL.md 增加心理深度，不重复 IDENTITY.md
- [ ] IDENTITY.md 无情感/心理推测
- [ ] SKILL.md 引用 SOUL.md 和 IDENTITY.md 作为配套文件
- [ ] 所有标准文件在同一目录下
- [ ] 安全版本已创建（可选，根据用户偏好。主 SKILL.md 本身可作为折中方案承载模式分离，不依赖单独的安全文件）
- [ ] 安全版本大小为完整版的 50-70%（如创建）
- [ ] 单源声明标记了 `[单源]`
- [ ] SKILL.md 有角色口吻的子Agent委托章节
- [ ] **幼年/儿童外形角色必须有安全边界** — 检查所有文件（prompt.md, SKILL.md, 主模板, 安全变体）
- [ ] **prompt.md 和 prompt.safe.md 的核心描述一致** — 相同角色特质、相同情感基调；安全版本更轻但不矛盾
- [ ] **共情/情感描述不是绝对的** — 检查 SOUL.md、prompt.md 和主模板中是否有"无法共情"/"难以共情"的表述
- [ ] **推测性关系已明确标注** — 检查 IDENTITY.md 关系表中非官方推断是否有 `[推测性互动]` 标签
- [ ] **Markdown 表格格式有效** — 没有跨不相关字段的合并单元格（如将神之心/武器/命之座写在一行），没有多余的前导竖线
- [ ] **安全版包含「用户指令优先」规则** — 检查所有 safe 版本文件中是否有显式的用户指令高于角色约束的声明
- [ ] **普通版包含「用户强烈要求时可跳过角色」机制** — 检查 prompt.md 和 SKILL.md 中是否有用户坚持时可脱离角色的规则
- [ ] **SOUL.md 包含上层「RP行动指南」** — 不应是一整份心理分析报告。上层应有具体温暖行为示例，深层心理标注为可选
- [ ] **prompt.md 包含「上下文感知模式选择」指令** — 低开销则保持扮演，高开销则保护能力，角色冲突则用 clarify 询问
- [ ] **双语输出规则已配置** — 当角色源语言与用户语言不一致时，prompt.md 和 SKILL.md 的 RP 核心指令中包含此规则：主文本用户语言，仅外语 `> 角色源语言原文`
- [ ] **技能目录不含特定角色文件** — `~/.hermes/skills/creative/character-roleplay-templating/` 中不应有任何角色的 prompt/SOUL/IDENTITY/SKILL 或命名模板。角色文件应存于工作区目录或独立的 `act-as-<角色名>` 技能
